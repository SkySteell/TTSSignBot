# TTSSignBot — Bybit DEMO futures

## Безопасность и текущее состояние

**В этой версии реальные сделки (MODE=live) намеренно запрещены.**
Код из ветки `audit/demo-150-safety-20261114` не развернут автоматически на BotHost. Сначала выполните проверки на отдельном демосчёте и сохраните резервную копию состояния.

Это экспериментальный торговый бот. Положительная статистика на 9 сделках не доказывает прибыльность. Используйте отдельные демо-ключи Bybit. Не выдавайте ключу право вывода средств.

## Настройки окружения BotHost

| Переменная | Назначение |
| --- | --- |
| `TG_TOKEN` | Токен Telegram-бота |
| `TG_CHAT_ID` | ID чата для уведомлений |
| `TG_ADMIN_ID` | Числовой **User ID** владельца, обязателен для управляющих кнопок в группе |
| `BYBIT_KEY` | API-ключ **демосчёта** Bybit |
| `BYBIT_SECRET` | Секрет **демосчёта** Bybit |
| `MODE` | **demo** (любое другое значение блокирует торговый режим) |
| `CAPITAL` | **150** (USDT, предел для расчёта риска, а не команда пополнения) |
| `STATE_FILE` | При необходимости путь к постоянному файлу состояния |
| `UNIFIED_ACCOUNT` | По умолчанию `1` для UTA |

Если ключи Bybit отсутствуют, `bot.py` работает только как сигнальный бот.

## Торговая конфигурация

- Риск на сделку **до 1% расчётного капитала**, включая предполагаемые комиссии и проскальзывание. На резком рынке фактическая потеря может быть больше.
- Плечо не более **3×**, предполагается **изолированная маржа**.
- До **2** позиций одновременно; дневной порог убытка **3%**, порог просадки **10%**.
- Фиксированный срез топ-10 по капитализации на 14 ноября 2026 (без стейблкоинов и производных токенов): **BTC, ETH, BNB, XRP, SOL, TRX, HYPE, ZEC, XMR, DOGE**, дополнительно **KAS**.
- Биржа должна подтвердить наличие активного USDT-linear perpetual для каждой пары. Недоступные пары пропускаются с уведомлением, автоматическая замена не производится. Фактически доступное количество может отличаться от 11.
- Торгуются только one-way позиции. На Hedge Mode бот останавливает входы.

## Обновление работающего бота

1. **Сохраните копию** действующей версии кода и `trader_state.json` в безопасное место. Не публикуйте файл с историей и конфигурацию с ключами.
2. Проверьте на Bybit DEMO открытые позиции и наличие биржевых SL и TP. Любые непроверенные позиции требуют ручного решения до запуска.
3. В BotHost настройте только `MODE=demo`, реальные **демо API-ключи**, `CAPITAL=150` и `TG_ADMIN_ID`. Убедитесь, что баланс демосчёта достаточен: значение `CAPITAL` деньги не начисляет.
4. Заранее проверьте, что путь `STATE_FILE` на BotHost сохраняется при перезапуске/обновлении; в противном случае настройте постоянное хранилище и резервирование.
5. Запускайте сначала на отдельной тестовой копии/инстансе. **Не запускайте два экземпляра с одним торговым API-ключом и Telegram-токеном**: они могут конфликтовать и создавать дубли.
6. Вручную проверьте кнопки `Статус`, `Пары`, `Пауза`, `Продолжить`; затем выполните контролируемую демосделку с проверкой SL/TP и `Closed PnL`.
7. Только после успешной проверки вручную переключайте рабочий BotHost на новую версию.

## Файлы состояния

- `trader_state.json`: локальное состояние ордеров, ограничений и статистики.
- При первом запуске новой версии прежние записи `closed` перемещаются в `legacy_closed`; они **не удаляются**, но не участвуют в новой подтверждённой статистике.
- Флаг `pending` указывает, что при прошлом запросе результат отправки ордера остался неопределённым. Бот блокирует новые сделки до ручной сверки и восстановительных действий.
- `halted` — аварийная остановка. Не удаляйте `trader_state.json` ради сброса лимитов: это опасно при незакрытых позициях.
- `STOP` в рабочем каталоге запрещает новые сделки, но не закрывает открытые позиции.
- После потери состояния при наличии позиций бот блокирует торговлю, не пытается автоматически их принять за свои.

## Тестирование (без API-ключей)

```bash
python -m pip install -r requirements.txt
python -m compileall -q bot.py tg_ui.py bybit_futures_signal_bot.py bybit_futures_trader.py
python -m unittest discover -s tests -v
```

Примечание: автоматические тесты проверяют код на симулированных ответах. Они **не заменяют** реальную интеграционную проверку на Bybit DEMO. Не переключайтесь на `live`: эта версия его отвергает.
